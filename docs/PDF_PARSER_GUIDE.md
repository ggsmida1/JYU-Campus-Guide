# 课表 PDF 解析器 — 实现文档

## 一、它能做什么

把教务系统导出的课表 PDF 文件，自动识别出里面的每一门课程，提取课程名、教师、地点、星期、节次、周次等信息，导入到小程序的课表里。

像这样：

```
PDF → 解析 → 
  计算机视觉 讲课 周一 1-2节 1-17周 锡科404 郭江鸿
  软件工程   实验 周三 1-2节 1-17周 锡科402 魏彩珍
  ...
```

## 二、核心思路：为什么不用 AI 识别

很多人第一反应是"用 OCR 文字识别"，但教务系统 PDF 里的文字是可以直接提取的——就像你在 PDF 里选中一段文字然后 Ctrl+C 复制一样。解析器的核心就是：把 PDF 里的文字提取出来，然后用规则找出每门课程的信息。

## 三、实现原理

### 3.1 提取文字 — pdf2json

`pdf2json` 这个库能把 PDF 里的每个文字片段提取出来，包括：
- **文字内容**：如"计算机视觉★"
- **坐标位置**：x（左右）、y（上下）

有了坐标，就能判断文字在表格的哪一列（星期几）、哪一行（第几节）。

### 3.2 判断星期几 — 表格列线

PDF 的课表是一个表格，表格有**竖线**（列分隔）和**横线**（行分隔）。pdf2json 能提取这些线的位置。

```
列线(x):  1.0   3.9   6.2   12.7  19.2  25.7  32.2  38.6  45.1  51.6
          ↑时间段 ↑节次 ↑周一  ↑周二  ↑周三  ↑周四  ↑周五  ↑周六  ↑周日  ↑右边界
```

"星期一"到"星期日"的表头文字落在哪个列区间，那一列就是对应的星期。文字在哪一列，课程就在星期几。

### 3.3 提取课程信息 — 正则匹配

所有课程的文字都有固定特征：

```
课程名★(1-2节)1-17周/场地/教师/教学班/...
课程名○(3-4节)1-17周(单)/场地/教师/教学班/...
```

用正则表达式匹配这个模式：
- **课程名**：类型标记（★○●◇◆）之前的文字
- **节次**：`(1-2节)` 这种括号里的数字
- **周次**：`1-17周`、`1-17周(单)`、`11周,15周` 等
- **场地/教师**：按 `/` 分隔后取对应位置的字段

> ★ = 讲课、○ = 实验、● = 实践、◇ = 上机、◆ = 讨论

### 3.4 两种 PDF 格式

不同学期的教务系统导出的 PDF 格式不完全一样：

**标签格式**（有明确标签）：
```
校区:江北校区/场地:锡科404/教师:郭江鸿/教学班:...
```

**无标签格式**（纯分隔）：
```
/田师208/朱阅岸/数据库系统原理-0002/...
```

解析器会先检测是哪种格式，然后用对应的方式提取字段。

### 3.5 列聚合策略

对于无标签格式，课程名和字段数据可能分开在两处：课程名在表格上方，字段数据在表格单元格里。解析器会把**同一列的所有文字拼接**起来，然后在整列文本中用正则找出每门课。这样即使名字和数据分开了，只要在同一列就能对上。

## 四、遇到的难题和解决方案

### 难题 1：跨页文本断裂

**现象**：一门课的名字被截成两半，前半在上一页末尾，后半（带★标记）在下一页开头。

```
页1末尾：人畜共患病防控与公共
页2开头：卫生安全★
```

导致解析器把"卫生安全★"当成一门独立课程，真正的课程名丢失。

**解决方案**：在列聚合之前，检测页边界处的不完整文本。如果上一页最后几行有"纯中文、无标记、较短"的文本块，就把它当作"挂起的半截课程名"。然后去下一页找续接的尾巴（含★标记的短文本），通过下一页后续的字段数据（教学班名称）来验证它们是否真是同一门课。验证通过后，拼接两段文本。

```
人畜共患病防控与公共 + 卫生安全★ → 人畜共患病防控与公共卫生安全★ ✅
```

### 难题 2：多页 PDF 的 y 坐标阈值

**现象**：PDF 第 1 页上方有标题、"时间段/节次/星期一…"表头等噪音，需要跳过（y < 3.8）。但第 2 页上方没有表头，直接就是课程数据。用同样的 y > 3.8 阈值会把第 2 页顶部的内容全部过滤掉，导致整个 9-10 节时段的课程丢失。

**解决方案**：按页号区分阈值。

```
第1页：y > 3.8（跳过表头）
第2页及以后：y > 0（不跳过）
```

### 难题 3：无类型标记的课程

**现象**：体育课、艺术课等没有 ★○●◇◆ 标记。

```
体育-排舞 2
(3-4节)1-17周/健美操房201/廖玫/...
```

正则按"课程名+类型标记"的模式找，匹配不到这类课程。

**解决方案**：两轮扫描。第一轮找有标记的课程（★○●◇◆），第二轮兜底找无标记的课程——只要看到有 `(X-Y节)` 且前面有像课程名的文字就收录。

### 难题 4：嵌套 wx:for 的 index 覆盖

**现象**：课表页面三层嵌套循环（行→列→课程匹配），最内层循环的 `index` 变量覆盖了外层的节次索引，导致课程卡片只显示了一门。

**解决方案**：用 `wx:for-index` 给每层循环的索引变量起不同的名字（`slotIdx`、`dayIdx`、`courseIdx`），避免覆盖。

### 难题 5：同名课程跨列混淆

**现象**：同一门课的讲课和实验分别在周一和周二，它们的课程名相同（如"计算机视觉★"和"计算机视觉○"）。解析器在匹配课程名字符串时，可能把周二的课程名匹配到周一的字段数据上。

**解决方案**：用"课程名 + 类型标记"组合来区分不同列的课程。优先匹配 `计算机视觉★` 而不是 `计算机视觉`。

## 五、用户（莫顺彬）参与贡献的关键点

### 5.1 网格定位思路

> "利用星期数的列宽都是一致的不会改变，可结合一周内同一列宽出现数量的检测和统计进行判断"

用户指出：PDF 表格的列宽是固定的，不管哪个节次，同一列的数据 x 坐标都是一致的。应该**统计所有时段内文本块的 x 坐标出现频率**，频率峰值就是列的真实位置。而不是只看表头行的位置。

这个思路直接催生了**全局频率统计算法**：对所有数据文本块的 x 坐标按 0.5 精度分桶统计次数，找出最高频的几个位置作为列中心，再配合表头位置精调。

### 5.2 正则边界切分思路

> "根据'节'、'周'、'校区'、'场地'、'教师'等关键字提取需要的相应内容"

用户反复强调：不要纠结于复杂的坐标聚类，直接用**关键字正则**去找课程数据。课程的生命周期是：**课程名 + 类型标记 → (X-Y节) → 字段数据 → 学分结束**。找到规律后按这个模式切分即可。

这个思路最终成为解析器的核心——按 `课程名[★○●◇◆](X-Y节)` 的正则模式在列文本中切分课程。

### 5.3 跨页断裂修复建议

> "课程名可通过检测到课程类型标记来判断完整课程名"

用户指出：完整课程名结束于类型标记（★○●◇◆）。如果上一页末尾的文字没有类型标记，说明它是断裂的。程序应该向下扫描下一页，直到找到这个断裂的尾巴。

### 5.4 周次计算优化

用户反馈学期开始日期的设置不够灵活，需要允许用户自己调整。根据反馈添加了**课表页点击「学期始: xxxx」直接修改**的功能。

### 5.5 全校课表实地验证

用户提供了**4 份不同学期、不同格式**的真实课表 PDF 进行测试验证：

- 莫顺彬(2023-2024-2) — 标准标签格式，含跨页断裂
- 莫顺彬(2024-2025-2) — 标签格式，含无标记体育课
- 莫顺彬(2025-2026-2) — 标签格式，奇偶周课程
- 黄浩城(2025-2026-1) — 无标签格式，2页，含第11节，跨页多门课

正是这些多样化的真实数据，检验和推动了每次改进。

## 七、总结

这个解析器的核心思路经历了从"坐标表格定位"到"正则锚点切分"的转变。最终版本结合了两种思路的优点：

1. **用表格列线定位星期几**（准确可靠）
2. **用正则锚点在列文本中切分课程**（简洁高效）
3. **用全局频率统计精调列位置**（适配不同 PDF）
4. **用挂起缓冲区处理跨页断裂**（鲁棒性强）
